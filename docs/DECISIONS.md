# Decisions (date · question · choice · reason · how to reverse)

- 2026-05 · Can the Windows/PySide6 agent be built here? · **No.** Build the verifiable parts as a Next.js + Postgres app (notch UI, safety/approval/router/engine reference implementation, red-team suite) and document the port. · Sandbox is Linux; Win32/UIA/Core Audio/Qt cannot run or be tested; claiming otherwise would be dishonest. · Reverse: start the Python package from `ARCHITECTURE.md` mapping.
- · Spine repo? · Wyzer (typed registry, bound approvals, evidence-based task engine). Port from Aemyos only provider adapters/Edge TTS/signing/test cases. · Audit. · Reverse: n/a.
- · Port Aemyos regex destructive guards? · **No**; replaced by tool-assigned tiers + argument-level escalation. · Regexes are bypassable (see AUDIT). · Reverse: add as an extra escalator in `policy.classify`.
- · LLM in tests/demo? · Deterministic scripted fake provider, clearly labelled; Claude and Ollama adapters written but enabled only with `ANTHROPIC_API_KEY` / `OLLAMA_MODEL`. · No keys/Ollama in sandbox; spec says use a fake provider. The fake is *not* product routing logic. · Reverse: set env keys.
- · Offline guard depth? · Application-level (`netGate`), counters tested. · Socket-level patching of the Node runtime is risky and untestable against a real firewall here. · Reverse: patch `net.Socket.connect` + `dns.lookup` in `netguard.ts`.
- · Path chars `%` rejected · conservative: env-var style segments are never expanded by tools, but rejecting removes a class of confusion. · Reverse: remove `%` from the BAD_CHAR regex in `policy.ts`.
- · Reading anything under protected paths is T3 (not only writes) · conservative; read of SSH keys / browser DBs must be blocked, and splitting read/write per path adds bypass surface. · Reverse: relax per-mode in `classify`.
- · Taint tracking is turn-wide: once any untrusted tool output enters context, every later T≥1 approval card carries "This came from page/file content." and `remember` is refused. · Over-warns, never under-warns. · Reverse: track taint per argument.
- · T2 "physical confirm" in a browser = a trusted click or Ctrl+Shift+Y; the server cannot truly verify physicality. Documented as a gap; Windows build should use a low-level input hook / secure attention. 
- · Voice-injection defence in the browser = half-duplex gate + server rejection of `voice` approvals flagged `loopbackOverlap`. Real WASAPI-loopback correlation not built.
- · Wake word in browser · not available; Alt+V toggles listening, "Hey Vox" is label only. 
- 2026-11-04 · Is the native implementation blocked solely because this environment is Linux? · No; build and test portable safety foundations now, leaving Windows integrations unverified. · Python policy components can be exercised safely with fake inputs here. · Reverse: remove the standalone `vox` package if the native integration adopts a different compatible foundation.
- 2026-11-04 · How should unverified voice approvals behave? · Fail closed unless a trusted future audio adapter explicitly confirms loopback was clear; T2 still rejects all voice approvals. · No loopback correlation exists yet. · Reverse only after implementing and testing a trustworthy loopback check.
- 2026-11-04 · Which branch should carry this work? · Keep the existing Arena session branch instead of creating `autonomous/<milestone>`. · The session requires all work on its fixed branch; do not merge to main. · Reverse only if the session branch policy changes.
- 2026-11-04 · What should UI-first work target? · Build a native PySide6/QML design studio with simulated states before core integration. · The user prioritized UI/UX; fakes avoid executing real actions while the safety gate is incomplete. · Reverse by replacing the demo model with the verified event-bus adapter after safety integration.
- 2026-11-04 · How should the prototype notch handle input? · Make the entire preview window click-through and control it from the studio. · Its approval and settings controls must not appear functional before a trusted input path exists. · Reverse when a real Windows input mask and secure approval flow are implemented and tested.
- 2026-11-04 · How to begin connecting the UI without a complete safety gate? · Wire only two explicitly labelled, in-memory scripted scenarios through a background worker and bound sandbox approvals. · User requested integration, but real desktop actions, trusted input and production policy are not ready. · Reverse by replacing the demo engine with the validated native core after safety and Windows tests pass.
- 2026-11-04 · How to introduce a real native capability before broad tool safety exists? · Expose only the T0 Windows Notepad launcher via a closed Pydantic-validated local-model registry; offer `--dry-run` and require an explicitly configured model. · It is a narrow, reversible first vertical slice, with no free-form executable, path, shell or consequential tools. · Reverse by disabling `--text` or replacing the registry with the reviewed Wyzer-derived execution gate.
- 2026-11-04 · What should happen when model output contains an unverified action claim? · Discard it and return only tool evidence or a conservative failure. · No production evidence-grounded follow-up or acceptance benchmark exists yet. · Reverse after implementing and testing an evidence-grounded follow-up.
- 2026-11-04 · Which provider should be default now? · ChatGPT plan via the documented Sign in with ChatGPT OSS OAuth and Responses API; defer Ollama as an explicit optional provider. · User requested online ChatGPT OAuth and the official public flow supports it. · Reverse by changing `--provider` default to `ollama` after local-model acceptance testing.
- 2026-11-04 · How to handle OAuth before live Windows validation and safe cross-process refresh? · Use Windows DPAPI, validate PKCE/state/JWKS/nonce/scopes, and require explicit re-sign-in on expiry; do not implement unsafe concurrent refresh or pretend revocation exists. · The sandbox cannot access OpenAI hosts or Windows DPAPI and refresh tokens rotate. · Reverse by implementing serialized refresh, revocation, account management and Windows/live tests.

- 2026-11-04 · How to make the first downloadable Windows test build honest and safe? · Package a separate unsigned, online-only early preview with dry run checked by default and only fixed Notepad as an actionable tool; do not bundle voice or present it as the full agent. · The live service and Windows implementation have not been validated, and production policy and voice are not present. · Reverse after the full acceptance criteria pass.
- 2026-11-04 · How should preview stop work? · Set a cooperative cancellation flag and check it before tool invocation; keep the worker busy until the network call returns and warn that already-started actions cannot be undone. · Python threads cannot safely preempt blocking I/O and there is no isolated production worker. · Replace with verified process isolation and a real emergency stop before broader tools are enabled.
- 2026-11-04 · How to build for Windows from Linux? · Trigger the Windows hosted GitHub workflow on the fixed Arena branch and download its limited preview artifact; do not modify or merge main. · Local cross-compilation and Windows desktop testing tools are unavailable. · Reverse by using a verified clean Windows build machine.
