- · Offline guard depth? · Application-level (`netGate`), counters tested. · Socket-level patching of the Node runtime is risky and untestable against a real firewall here. · Reverse: patch `net.Socket.connect` + `dns.lookup` in `netguard.ts`.

- · Reading anything under protected paths is T3 (not only writes) · conservative; read of SSH keys / browser DBs must be blocked, and splitting read/write per path adds bypass surface. · Reverse: relax per-mode in `classify`.
- · Taint tracking is turn-wide: once any untrusted tool output enters context, every later T≥1 approval card carries "This came from page/file content." and `remember` is refused. · Over-warns, never under-warns. · Reverse: track taint per argument.
- · T2 "physical confirm" in a browser = a trusted click or Ctrl+Shift+Y; the server cannot truly verify physicality. Documented as a gap; Windows build should use a low-level input hook / secure attention. 
- · Voice-injection defence in the browser = half-duplex gate + server rejection of `voice` approvals flagged `loopbackOverlap`. Real WASAPI-loopback correlation not built.
- · Wake word in browser · not available; Alt+V toggles listening, "Hey Vox" is label only.

- 2026-11-04 · Which provider now? · Use a user-supplied Groq API key for the real voice UI; keep earlier ChatGPT/Ollama CLI paths separate and do not ask for the key in chat. · User changed provider priority to Groq; Windows DPAPI protects the saved key. · Reverse by adding an explicit provider selector after provider validation.
- 2026-11-04 · Enable unlimited desktop actions immediately? · No; enable only fixed built-in apps and HTTPS browser navigation with argument-bound, expiring click approval, and reject all other model actions. · General execution and destructive actions are unsafe without the requested production policy, cancellation and Windows tests. · Expand tools incrementally after their policies and disposable Windows tests pass.
- 2026-11-04 · How to activate voice before wake-word/loopback safety exists? · Use bounded explicit push-to-talk, record in memory, close the mic before TTS, never use voice for approval, and disclose that audio/transcripts go to Groq. · Avoid unintended continuous recording and speaker-output self-approval. · Add wake word, VAD and verified loopback correlation after adversarial audio testing.
- 2026-11-04 · How to implement folder opening safely? · Accept only known-folder aliases or validated absolute local Windows paths; resolve canonically with `SHGetKnownFolderPath` for redirected user folders; bind the approval to the resolved path and revalidate before `os.startfile`; reject UNC, device, relative, ADS and control-char paths. · Known folder GUIDs are stable but redirection means hardcoded `Path.home()` would be wrong; binding prevents path-swap approval replay. · Reverse after implementing a reviewed policy allowlist and removing the direct folder tool if production policy requires a stricter boundary.
- 2026-11-04 · How to implement text typing safely? · Model emits exact text plus an optional target hint; local UI enumerates visible windows with focused controls and requires explicit user selection; bind text plus window handle, PID, creation time, title, class and focus child to single-use approval; recheck identity and foreground before `SendInput`; reject control/newline/tab/bidi-invisible characters initially; report partial input honestly. · Window titles and handles must never reach the model; foreground can change between check and queue, so perfect target binding cannot be guaranteed. · Reverse by removing the typing tool until a verified isolated worker and production focus/audit path exist.
- 2026-11-04 · Why use `SendInput` Unicode instead of clipboard or raw keystrokes? · `KEYEVENTF_UNICODE` preserves exact UTF-16 code units without clipboard history exposure or vk mapping limits; no Enter/Tab is added. · Clipboard would leak text to other apps and lose timing; vk mapping breaks for non-ASCII. · Reverse if a future verified text-target API provides stronger binding and evidence.

- 2026-11-04 · How to add scroll and window management safely? · Reuse the same local window enumeration and explicit user selection as typing; bind each action to the selected WindowRef; recheck identity before sending scroll/ShowWindow/PostMessage; scroll uses MOUSEEVENTF_WHEEL via SendInput, window management uses ShowWindow/PostMessageW with bounded counts. · These are common, reversible actions that share the existing approval and identity-check infrastructure; adding them avoids a separate unsafe surface. · Reverse by removing them if a future reviewed policy requires stricter boundaries or verified isolated workers.

- 2026-11-04 · How to add file operations and screenshots safely? · Accept only validated absolute local Windows paths; bind exact source/destination or target path to single-use approval; reject UNC, device, relative, ADS and parent-traversal paths; use `shutil.copy2`/`shutil.move`/`Path.unlink` for file ops; use `BitBlt` for screenshots with optional PIL or manual BMP fallback. · These are common, reversible (copy/move) or destructive (delete) actions that need explicit approval; path validation prevents traversal and ADS attacks. · Reverse by removing file-delete or screenshot tools if a future reviewed policy requires stricter boundaries.

- 2026-11-04 · How to diagnose stalled Windows suite without repeating the same full-suite runs? · Split tests into independent file-level Windows jobs and preserve explicit time limits; build the limited installer separately while stating checks may fail. · Multiple combined jobs previously hung and prevented actionable results. · Restore a single gating job after root cause and full acceptance are verified.

- 2026-11-04 · Should the agent be able to read the clipboard? · No. The clipboard is write-only: `set_clipboard` replaces it only with registry-validated text (≤1,000 visible characters, no control/bidi) that the user approved verbatim via a single-use, argument-bound approval; clipboard contents are never read, returned as evidence, spoken, or sent to a provider. `system_info` is read-only and deliberately excludes user/host names because result evidence may be spoken through the online speech service. · Clipboard contents are untrusted and frequently contain passwords, keys or OTPs; the native slice has no redaction/untrusted-output pipeline, and an approval for a read would have to happen before the user could see what disclosure they were approving. A draft `read_clipboard`/`write_clipboard` Win32 implementation was removed/rewritten for this reason and because it ignored `GlobalLock` pointers, omitted the `CF_UNICODETEXT` NUL terminator, and risked 64-bit handle truncation without ctypes signatures. · Reverse only after a reviewed redaction + untrusted-output pipeline exists and read results are local-display-only (never model or TTS input).

- 2026-11-04 · How to keep strict mypy green on both Linux and Windows? · Win32-only ignores use `# type: ignore[attr-defined, unused-ignore]` so the same source passes with the platform-default and `--platform win32` type checking; verify with both invocations locally before pushing. · Windows CI run 41869216636 failed lint because strict `warn_unused_ignores` reports those comments as unused on Windows, while Linux requires them; weakening strictness per-module would hide genuinely stale ignores, and `getattr` shims would obscure every Win32 call site. · Reverse if a future mypy version changes multi-code ignore semantics; re-run both platform checks after any mypy upgrade.

- 2026-11-04 · How to parametrize oversized-payload tests portably? · Always give large binary/text parameters short explicit `ids=[...]` (e.g. `oversized-line`), never let the value become the node ID. · pytest copies the node ID into the `PYTEST_CURRENT_TEST` environment variable during setup/teardown; Windows caps environment variables at 32,767 characters, so the 65,537-byte and 1,048,577-byte parameters raised `ValueError` before the tests ran and made the Windows suite fail/crawl for reasons unrelated to product code (Linux allows ~128 KB, hiding the bug). Diagnosed by emitting pytest failure tails as check annotations, since job-log hosts are unreachable from the dev sandbox. · Reverse only if pytest stops mirroring node IDs into the environment; keep IDs short regardless for readable `-v` output.

- 2026-11-04 · Push-to-talk or hands-free wake word? · Hands-free, per user request: an opt-in toggle replaces the Record/Finish buttons. While on, microphone frames go only to an on-device Vosk small-en recognizer spotting "Hi Vox" (plus common mis-hearings like "hey box", since "Vox" is out-of-vocabulary for small models); no audio is sent to Groq until after the wake phrase, the request is silence-endpointed, and listening resumes automatically after the (half-duplex) spoken reply. The ~40 MB Apache-2.0 model is bundled in the installer (source installs download it once on first enable). Consequential actions still require click approval — there is no speaker verification, so anyone in earshot can wake Vox — and wake spotting pauses while an approval card is open. Vosk was chosen over openWakeWord because it needs no per-phrase trained model for a custom phrase and ships a `py3-none-win_amd64` wheel; Porcupine was rejected (proprietary key/licence). · Reverses the earlier "explicit push-to-talk only" stance at the user's direction, keeping the privacy boundary (local wake detection, visible mic indicator, one-switch off) that made push-to-talk safe. · Reverse by removing the toggle/controller and restoring the Record/Finish slots (`record_wav` push-to-talk capture is retained in `vox/voice/audio.py` and `GroqVoiceService.voice`).

- 2026-11-05 · How literal should wake-phrase matching be, and how do users diagnose a deaf wake word? · Match greeting+name token pairs, where greetings include strong forms (hi/hey/ok/okay, pairing with name variants box/fox/walks/wax/…) and weak mis-hearings (high/hay/he/i, pairing only with exact "vox"), plus merged forms ("hivox"); ordinary sentences like "a box" or "I walks" cannot match. Surface the spotter's partial/final snippets locally in the UI ("Heard locally", never sent online) with a mic-level meter. · First physical test (2026-11-05) reported "saying Hi Vox but it is not listening": with an out-of-vocabulary name and a small en-US model, exact matching is brittle across accents/microphones, and without local readouts neither user nor developer can distinguish mic-routing failure from mis-recognition. · Narrow the variant sets if false wakes are reported; move to a trained openWakeWord model if a "Hi Vox" model is ever trained and verified.

## Live Command Engine — reconciliation decisions (spec §3, logged 2026-11-05)

- L-01 · Contextualiser ≠ intent router: it only normalises language (references, ASR repair, fragment merge, turn-kind); never picks tools/tiers/answers; feeds the same single chat-with-tools request; A/B-gated in LE2. · Keeps the master-spec ban on routing models intact while enabling "close it"-style references. · Reverse by disabling the rewrite step (pipeline passes raw utterance through).
- L-02 · Deterministic control plane is a closed set only (stop/cancel, pause/resume/status, mic mute, yes/no-while-approval-pending), phrases in i18n EN+HI with parity test; no regex intent routing anywhere else. · Sub-150 ms deterministic stop without becoming a shadow router. · Reverse by removing `vox/engine/control.py` dispatch ahead of the model call.
- L-03 · Audit keeps tool-level records only (tool, tier, args hash + redacted args, approval, result); transcript text persists only with user opt-in. · Privacy non-negotiable 5 vs. total-event logging. · Reverse by widening the session-store write policy (requires new privacy review).
- L-04 · Follow-up window (~6 s after speaking/acting, setting, default on) is a deliberate extension beyond "wake only when idle". · Siri-class multi-turn feel; guarded by addressed-to-assistant + approval notes. · Reverse via the setting (0 s disables).
- L-05 · Per-turn provider fallback is separate from mode-level hysteresis; it never flips mode; both logged. · Resilience without mode flapping. · Reverse by pinning one provider per mode.
- L-06 · Tool-pack selection by retrieval only as a bench-validated prompt-size optimisation. · 15 schemas are small today (7.8 KB request); selection may never pay off. · Reverse by always sending the full ordered schema set.
- L-07 · Prompt v2 lives beside v1, versioned, `PROMPT_VERSION` logged per turn. Templates live in `vox/engine/prompts/v2/` (package data) rather than repo-root `prompts/v2/`. · PyInstaller ships package data reliably; identical versioning semantics. · Move the directory and adjust the loader path.
- L-08 · Memory writes from untrusted content stay blocked; learned preferences are proposals until confirmed (or repeated + confirmed). · Master §10 unchanged. · No reversal planned.
- L-09 · Undo is an ordinary tiered, approved tool call — no undo bypass. · Safety supremacy (non-negotiable 1). · No reversal planned.
- L-10 · "Hi Vox"/"Hey Vox" two-stage local wake (spec 4.0); phrases from config/i18n, never hard-coded; wake is a doorbell only (never approves/lowers tier); wake turns carry `trigger=wake` onto approval cards; stage-1/2 engine, licence and FA/FRR recorded in SPEECH_BENCH.md at LE1b. LE0 finding: current engine is single-stage Vosk unconstrained decode; openWakeWord (no trained "Hi Vox" model) and Porcupine (proprietary key) rejected — LE1b adds a VAD/RMS gate + Vosk verify with word confidences. · Builds on the shipped, Apache-2.0, already-bundled stack. · Swap the detector behind the same `WakeEngine` protocol.
